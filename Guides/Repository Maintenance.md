# Repository Maintenance

## Keeping the collection useful

- Keep prompt names descriptive and consistent.
- Prefer focused files that solve one well-defined problem.
- Update the README when adding a new category or directory.
- Review examples periodically for clarity, safety, and outdated assumptions.
- Remove duplicate prompts or combine them when one version is clearly better.

## Suggested review cycle

For each prompt, check the objective, context, constraints, output format, and safety considerations. Test important changes with representative inputs and record any limitations in the prompt or accompanying guide.

## Organization

Use `Prompts/` for standalone prompt examples, `Templates/` for reusable starting points, `Guides/` for explanatory material, and `Checklists/` for repeatable review steps. Keep filenames readable and avoid storing secrets or private user data.

## Version history

Use focused commits so improvements are easy to understand and revert. Prefer messages that describe the user-facing change, such as `docs: clarify evaluation workflow` or `feat: add research prompt template`.
